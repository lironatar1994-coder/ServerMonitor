# Design support

## Purpose
- Keep the design preview metadata and local review evidence aligned with the daily-check application.

## Ownership
- `design.json` extends the root `DESIGN.md` with preview metadata and self-contained component examples. Root `DESIGN.md` owns normative tokens and visual rules; frontend source owns the implementation.
- `review/` holds local screenshots, email previews and check results. It is ignored by Git and may contain internal metrics.

## Local Contracts
- Do not put credentials, tokens or copied customer messages in these artifacts.
- Refresh design metadata after a durable component or token change; do not treat a preview as application source.
- Email previews never send messages. Browser review uses the scripts and limits documented in `../ops/AGENTS.md`.

## Work Guidance
- Keep metadata factual and consistent with the final CSS cascade and shared React components.

## Verification
- Parse `design.json` as JSON and run `git diff --check` after metadata changes.
- The UI and email evidence is generated by the root `ops/` review scripts.

## Child DOX Index
- No child contracts.
